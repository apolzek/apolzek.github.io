# CLAUDE.md

Guidance for coding agents working on this repository.

## Project

Hugo static site using the [Hextra](https://github.com/imfing/hextra) theme (v0.11.1, vendored in
`_vendor/`) with the layouts and visual style of the AkitaOnRails blog. Personal blog of
Vinícius Gomes Batista (apolzek) at https://apolzek.github.io. Bilingual: Brazilian Portuguese is
canonical (`index.md`, served at `/`), English translations live in `index.en.md` next to it and
are served at `/en/`. The navbar has a PT | EN switch (`layouts/partials/custom/lang-toggle.html`).

## Commands

```bash
./scripts/generate_index.rb                  # regenerate content/_index.md + content/_index.en.md
hugo server --renderToMemory -p 1313         # dev server
hugo server -D --renderToMemory -p 1313      # dev server including drafts
hugo --minify                                # production build into public/
./scripts/tag_catalog.rb --search "topic"    # find a canonical tag
./scripts/tag_catalog.rb --check             # validate tags of every post
./scripts/dev.sh start|stop|logs|new-post    # Docker workflow
```

## Content

Posts live at `content/YYYY/MM/DD/slug/index.md`. Required front matter for a published post:
`title`, `slug`, `date` (ISO 8601 with `-03:00`), `description`, `tags`, `draft: false`.

- `content/_index.md` and `content/_index.en.md` are generated by `scripts/generate_index.rb`.
  Never edit them
  by hand. Re-run the script after publishing.
- Every published post must have both `index.md` (PT) and `index.en.md` (EN, with a translated
  `slug`, `title`, `description` and EN tags). Translate faithfully; never add content.
- Drafts (`draft: true`) are the old Jekyll `_writing/` folder. Some carry `secret: true`
  and `password:` from the old site; they must stay drafts until the author decides otherwise.
- Tags must exist in `data/tag_taxonomy.yml`: PT posts use the `pt` slug, EN posts the `en` slug.
  `scripts/tag_catalog.rb --check` validates both. Do not invent spelling or language variants.
- Images are served from `static/assets/img/` at `/assets/img/...`. Never delete an
  unreferenced image: it may belong to a draft or a future post.
- `content/dm/<slug>/index.md` are "Direct message" texts: hidden from home, search, RSS, sitemap
  and tag pages via `build.list: local`, `sitemap.disable: true` and no tags. Each declares `code:`;
  `/dm/` (layout `layouts/dm/list.html`) maps codes to URLs in client-side JS and the article layout
  (`layouts/dm/single.html`) bounces visitors without the sessionStorage mark back to `/dm/`.
  The code is intentionally exposed in the HTML. Never list these pages anywhere else.
- `data/thoughts.yml` feeds `/thoughts/` (fields: `text`, optional `text_en`, `image`, `alt`, `caption`;
  an image shows as an icon that opens a modal), `data/moments.yml` feeds `/moments/` (Instagram-style
  3-column square grid; fields `image`, `alt`, `caption`, `caption_en`, `date`; click opens a modal)
  and `data/cheatsheet.yml` feeds `/cheatsheet/`.
  `data/films.yml` and `_grimoire/` are personal notes, not rendered.

## Layouts

| File | Purpose |
|------|---------|
| `layouts/home.html` | Homepage (renders the generated `_index.md`) |
| `layouts/single.html` | Post page: centered content, TOC, tags, TL;DR link |
| `layouts/term.html` | Tag pages with list/grid toggle |
| `layouts/thoughts.html` | `/thoughts/` from `data/thoughts.yml`, client-side search |
| `layouts/moments.html` | `/moments/` from `data/moments.yml`, square photo grid + lightbox |
| `layouts/cheatsheet.html` | `/cheatsheet/` from `data/cheatsheet.yml`, tag filter + copy |
| `layouts/dm/list.html`, `layouts/dm/single.html` | Direct message: code input and the gated article page |
| `layouts/partials/custom/head-end.html` | Fonts, old-blog palette (white/purple light, #131418/pink dark, Catppuccin Mocha code), all custom CSS, homepage type-to-filter |
| `layouts/_partials/sidebar.html` | Sidebar links + top tags |
| `layouts/list.rss.xml` | RSS feed (shadows Hextra's, which uses the removed `.Site.Author`) |
| `layouts/baseof.html` | Adds the `#cosmos` canvas and loads `static/js/cosmos.js` (drifting star field from the old blog) |

Hextra's built-in FlexSearch is enabled (`params.search.enable: true`). Mermaid code fences
are rendered by Hextra.

## Deployment

GitHub Pages through `.github/workflows/pages.yaml` on push to `main`. The workflow runs the
tag check and `generate_index.rb` before building.
